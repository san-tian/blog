MTP 为什么会让上下文减小

开 MTP 之后可用上下文变短，直接原因是 KV cache pool 被 MTP 层和草稿槽位分走，而不是"模型参数变大了"。

0. 背景：MTP 是什么

MTP（Multi-Token Prediction，多 token 预测）指在标准的 next-token 预测之外，让模型一次性预测未来多个位置的 token。它最初是训练技巧，后来成了推理加速手段，这两种用途需要分开看。

用途做什么带来什么
训练目标 除了预测 t+1，额外预测 t+2 … t+k，多个损失一起回传 给主干更密的监督信号，表示学习更强。推理时可以完全不用这些额外头
推理加速 让 MTP 头先"猜"出后面几个 token（草稿），再由主干一次 forward 并行验证 一次 decode 迭代吐出多个 token，降低平均单 token 延迟

推理加速这条路属于 投机解码（speculative decoding）。经典投机解码要额外跑一个小模型当 drafter；MTP 的做法是把 drafter 做成主干自带的一两层，复用主干的 hidden state，因此参数开销很小、草稿质量还不错。

为什么投机解码能加速：自回归 decode 是访存受限的，batch 小的时候 GPU 算力大量空闲。主干验证 k 个草稿 token 的耗时接近验证 1 个的耗时，所以只要草稿有一定命中率，就能用几乎不变的时间换多个 token。加速的来源是把访存受限换成算力受限，不是减少了计算量。

本文关心的是它的副作用：草稿和验证都需要 KV cache 空间，而这块空间和上下文长度抢的是同一份显存。

1. MTP Layer 是哪来的：结构、训练、验证

这是最容易含糊的部分，拆成四个问题回答。

1.1 它从哪来

MTP 层不是主干的一部分，是额外挂在主干末端的模块，初始化方式有两类：

  • 新建 + 随机初始化后训练（DeepSeek-V3、GLM 系列的 MTP 层）：结构照抄一个 Transformer block，参数独立于主干，从头训。
  • 拷贝主干某个 block 作为起点（EAGLE 类 / Kimi K3 的 Draft 层做法）：用主干已有 block 的权重初始化，再单独微调。好处是起点就懂语言分布，收敛快。

两种方式的共同点：推理时它和主干是两套权重、两套 KV cache。这就是后面显存账要分开算的原因。

1.2 它的结构是什么

都是一个标准 Transformer decoder block：LayerNorm → Multi-Head Attention → 残差 → LayerNorm → FFN → 残差。三者真正不同的只有两头：

  • 输入侧的“投影”行：把主干给的东西整成 attention 能吃的形状。
    • 主干层：上一层直接给 x，不用投影。
    • MTP 层（GLM-5.2）：拿主干末层 hidden state ht，拼上一步草稿 token 的 embedding（ht ⊕ emb(上一草稿)），再线性投影回 dmodel。拼这个是为了让 MTP 知道“上一轮猜出了什么词”，从而接着往下猜。
    • Draft 层（Kimi K3 / EAGLE-3）：取主干多个层的 hidden state（如第 1/中/末层），拼接后线性投影回 dmodel。主干层的输出从左到右越来越抽象（低层偏 token、高层偏语义），多层级拼接让 draft 同时拿到不同粒度的信息，猜得更准。
  • 末尾的“LM Head / 展开”：主干层输出 hidden state 给下一层；MTP/Draft 层过共享 LM Head 出 logits，再按自己的方式展开成多个草稿 token。

1.3 它怎么训练出来

核心思路：冻结或弱扰动主干，只让 MTP 层学会"接着主干往下猜"。以 Kimi K3 的 Draft 层为例，是两阶段：

阶段一：预训练（学基本的多步预测能力）

  • 数据：常规预训练语料
  • 目标：shifted target，即位置 t 的 MTP 输出去拟合真实的 t+1（和普通 LM 一样的交叉熵）
  • 此时还没有"自己吃自己输出"的情形，训练是 teacher forcing 的

阶段二：后训练蒸馏（对齐真实推理时的分布）

  • 冻主干，只更新 Draft 层，避免拖坏主干质量
  • 展开 k 步模拟推理（K3 为 7 步）：第 1 步吃主干的多层特征（浅层/中层/末层拼接），第 2 步起吃 Draft 自己上一步的输出——刻意制造和推理一致的误差累积
  • 损失直接对齐接收率：L = −log Σ_v min(p_v, q_v)，其中 p 是主干分布、q 是 Draft 分布。Σ_v min(p_v, q_v) 正是拒绝采样下这一步被接受的概率，所以这是在直接优化"会被主干接受多少"，而不是用 KL 之类的代理目标
为什么第二阶段必要：只做 teacher forcing 训练的 drafter，在推理时会遇到训练时没见过的输入（自己的错误输出），越往后越偏，accept rate 掉得很快。展开训练把这个分布偏移提前暴露给模型。

GLM-5.2 走的是更省的路线：只有 1 层 MTP，训练时展开 3 步但三步共用同一份权重（权重绑定）。代价是三步能力不能各自特化，好处是参数只多 1.3%，且实测 accept length 达到 2.76，高于 DeepSeek-V3 的 2.55。

1.4 草稿怎么验证

验证由主干完成，一次 forward 覆盖全部草稿位置，逐位置判定接受还是拒绝。

  1. 拼接输入。把已确认的上下文 + k 个草稿 token 一起送进主干，构成长度 k+1 的一段待验证序列。
  2. 一次并行 forward。因果 mask 保证位置 i 只能看到 i 之前的内容，于是一次前向就同时得到"接受了前 0 个、前 1 个 … 前 k 个草稿"各种情形下的主干分布 p。这一步必须为 k 个位置准备 KV 槽位。
  3. 逐位置判定。贪心解码下就是比对：主干 argmax 是否等于草稿 token；采样解码下用拒绝采样，以 min(1, p_v/q_v) 接受，拒绝时从修正分布 norm(max(0, p−q)) 重采一个 token。
  4. 截断。遇到第一个被拒绝的位置就停，保留它之前的全部草稿，再补上该位置由主干（或修正分布）给出的正确 token。所以每轮至少产出 1 个 token，不会空转。
  5. 回收 KV。被接受位置的主干 KV 转为常驻，被拒绝位置的 KV 丢弃，MTP 层的草稿 KV 全部释放。
正确性保证：采样场景下用的拒绝采样方案（Leviathan 等提出）可以证明输出分布与直接从主干采样完全一致。投机解码不改变模型输出分布，只改变吐 token 的节奏。贪心场景则直接等价于主干贪心解码的结果。
但显存要按最坏情况留：验证发生在"知道接受几个"之前，所以 k 个草稿位置的 KV 槽位必须先分配好。accept rate 再高也不能少留，树形投机要留的是整棵树的节点数。这就是上下文被吃掉的直接机制。

2. 显存里到底发生了什么

推理显存主要由四部分组成：模型权重（静态）、KV cache（随 batch × 序列长度增长）、激活与临时 buffer、以及框架保留的碎片空间。长上下文场景下 KV cache 通常是最大的可变项，也是唯一被"上下文长度"直接放大的部分。

实际系统（vLLM / SGLang 等）的做法是：启动时先扣掉权重和必要 buffer，把剩余显存整体划成 KV cache pool，再按 block 分配。可用上下文长度本质上由这个 pool 的大小除以每 token 每层的 KV 字节数得到。开 MTP 之后，pool 要额外容纳 MTP/Draft 层的 KV 和草稿峰值槽位，留给主干的份额就变少了。

4. 为什么不是"参数变多"导致的

模型权重KV cache
规模依据参数量，固定batch × 序列长度 × 层数 × KV head 数
生命周期加载一次，常驻随请求动态申请与释放
MTP 的增量+1 层 ≈ 主干层数的 1/N（80-90 层模型约 1%）+1 层常驻 KV，再加草稿峰值槽位
是否随上下文放大否是，与序列长度成正比

所以"多了 1% 参数"和"上下文少了一截"之间没有直接因果。真正的链条是：额外的层和草稿槽位挤占 KV pool → 留给主干的 token 预算变少 → max_total_tokens 调小 → 单请求可用上下文变短。同样的 pool 被更多"每 token 每层"的条目瓜分，序列自然要变短。

5. 小结

  1. MTP 有两种用途：作为训练目标提供密集监督；作为推理时的自带 drafter 做投机解码。上下文变短只与后者有关。
  2. MTP Layer 是主干之外新增的同构 Transformer 层，常从主干 block 拷贝初始化，共享 embedding 和 LM Head，因此参数只多约 1%，但它和主干层一样要写 KV。
  3. 训练必须按推理的方式多步展开，否则草稿在第 2 步就会因为 exposure bias 崩掉。EAGLE-3 式做法进一步把损失直接对准接受率而非 KL 代理。
  4. 验证靠因果 mask 一次 forward 完成：线性草稿拼成一条序列，树形草稿用 tree_mask 让分支互不可见，然后沿树取被接受的最长路径。
  5. 显存按峰值预留，不按期望接受长度预留。树形投机要为整棵树的节点留槽位，这是它上下文损耗大于线性投机的原因。
  6. 输出分布不受影响：投机采样在数学上与直接从主干采样等价，换来的吞吐是"免费"的，付出的代价是显存和可用上下文。
