DCP: 动态上下文并行

破解长上下文训练的输入动态性难题
SOSP'25 Context Parallelism Long Context Training Hypergraph Partitioning

背景

Context Parallelism (CP) 是支持长上下文训练的关键技术，通过将序列分布到多个设备并行计算注意力来突破单卡内存限制。现有 CP 方法（RingFlashAttention、Ulysses、DeepSpeed-Ulysses 等）采用静态配置：为所有 batch 使用固定的并行度和数据分区方案。

然而，训练数据具有输入动态性：序列长度和 token 关系（注意力模式）在样本间存在巨大变异。静态配置无法适应这种动态性，导致冗余通信和计算不均衡。

核心问题

长上下文训练面临两类输入动态性：

1. 序列长度差异

训练数据中短序列远多于长序列。例如 LongAlign 和 LongDataCollection 数据集（论文图 2）：

  • 大部分序列长度 < 20K tokens
  • 但也有 100K+ 的长序列（占比小但训练成本极高）
  • Llama 3 预训练的 tuning 阶段：128K 上下文样本仅占 0.1%

静态 CP 的问题：短序列也按最长序列的通信模式传输 KV cache，产生冗余通信。论文图 5a 显示，8B GPT 模型在 EC2 p4d.24xlarge 集群（8 节点 × 8 GPUs）上训练时，16-way CP 的通信开销占总迭代时间的 36.7%。

2. 注意力模式多样

不同任务使用不同的注意力掩码（论文图 6）：

  • Causal mask：标准因果语言模型（每个 token 只能看到之前的 token）
  • Shared question mask：多候选答案共享同一个问题前缀（RLHF、多候选生成）
  • Lambda-shaped mask：结合注意力 sink 和滑动窗口
  • Block-wise mask：文档级块之间稀疏连接（检索增强生成）

静态 CP 的问题：为 causal mask 设计的分区方案应用到 sparse mask 时，会传输大量不参与计算的 KV 块。论文图 7b 显示，在 shared question mask 下，38/48 个 KV 块未被使用但仍被传输（冗余率 79%）。

静态 CP 的性能问题

通信冗余序列长度 × CP degree 决定通信量，短序列产生大量无效传输
计算不均衡不同设备间负载严重失衡（论文图 5c：长短序列混合时，某些设备空闲而其他设备过载）
掩码不兼容为 causal mask 优化的配置无法高效处理 sparse mask

DCP 方案

DCP (Dynamic Context Parallelism) 通过细粒度块级分区 + 动态映射解决输入动态性问题。核心思想：为每个训练 batch 动态生成最优的并行配置，而不是使用全局固定配置。

1. 块级数据和计算分区

DCP 将注意力计算抽象为两类块（论文图 9、10）：

数据块（Data Block）

Q、K、V、O 张量的连续切片：

  • Q、K、V 形状 [B, H, L, D]（batch、head、seq_len、hidden_dim）
  • 按 batch 和 seq_len 维度划分为 H × B_b × B_q 个 Q 块和 B_b × B_kv 个 KV 块
  • 块大小是超参数（如 Q/KV 块 256 tokens）

计算块（Computation Block）

描述一对 Q 块和 KV 块之间的注意力计算：

  • 一个 Qi 块和 KVj 块的计算产生输出块 Oi
  • 计算公式：Oi = Softmax((Qi × KjT) / √D) × Vj
  • 关键优化：如果注意力掩码 Mij = 0（全部被 mask），则跳过该计算块
统一表示的威力：数据块 + 计算块的抽象统一描述了所有 CP 配置。论文图 5 展示：(a) 传统 ring attention、(b) pure DP（无通信但计算不均）、(c) 长序列用 CP + 短序列用 DP 的混合配置，都可以表示为不同的块到设备映射。

2. 超图分区优化映射

将块到设备的映射建模为超图分区问题（Hypergraph Partitioning，论文图 12）：

超图构建

  • 顶点 (Vertex)：
    • 数据块（Q、KV、O）+ 计算块
    • 顶点权重 = 数据块大小（bytes）+ 计算块 FLOPS
    • 例如：Q 块权重 = head_dim × block_size × 2 bytes（BF16）
    • 计算块权重 = 2 × head_dim × Q_size × KV_size FLOPS
  • 超边 (Hyperedge)：
    • 连接一个计算块与其输入/输出数据块（1 个计算块 + 1 个 Q 块 + 1 个 KV 块 + 1 个 O 块）
    • 超边权重 = 数据块大小（跨设备传输成本）

优化目标

minimize Σ_{e∈E} s_e(λ_e - 1)  # 跨设备通信量
subject to:
  w(P_i) ≤ [1+ε, 1] ⊙ w(N)/R  # 负载均衡约束

其中：

  • s_e：超边 e 的权重（数据块大小）
  • λ_e：超边 e 连接的顶点被分配到的不同设备数（1 表示所有顶点在同一设备，无通信）
  • w(P_i)：设备 i 的总权重（计算 + 内存）
  • w(N)/R：平均每设备负载（R 是设备数）
  • ε：负载不均衡容忍度（如 0.03，表示允许 3% 偏差）

层级分区

由于机器间通信（NIC）比机器内通信（NVSwitch）慢得多，采用两级分区：

  1. 机器级分区：优先最小化跨机器通信（带宽低、延迟高）
  2. 设备级分区：在每台机器内优化设备间通信

使用 KaHyPar 等高效启发式算法求解（超图分区是 NP-hard 问题）。论文使用 multi-level 启发式：coarsening（粗化）→ initial partitioning（初始分区）→ refinement（细化）。

3. 多路分治调度

块到设备的映射确定后，需要生成每个设备的执行计划（论文 Listing 3）：

调度策略

  1. 将每个设备的计算块按通信需求分为 T 个 division（如 T=4）
  2. 第 1 个 division：调度最少通信的块（优先执行不依赖远程数据的计算）
  3. 后续 division：按通信量递增调度
  4. 每个 division 内的操作使用 fused kernel（Triton）执行：
    • Attention 计算（基于 FlashAttention）
    • Reduction（多个计算块贡献同一输出块时聚合）
    • Copy（管理块级缓冲区）
    • Comm Launch（异步启动下一 division 的通信）
通信隐藏：通过分 division 调度，division i 的计算可以与 division i+1 的通信重叠，最大化 GPU 利用率。

4. 系统架构

DCP 系统包含三个模块（论文图 8）：

模块职责运行时机
Data Loader 预取序列长度和掩码模式，触发 Planner 训练迭代开始前（CPU 异步）
Planner • 生成数据块和计算块（Block Generation）
• 超图分区求解最优映射（Placement w/ Hypergraph）
• 生成每设备执行计划（Comp. & Comm. Scheduling） 		与 GPU 训练流水线重叠（lookahead κ 迭代）
Executor • 块级缓冲区管理（按类型索引复用，避免频繁分配）
• 执行 DCP instructions（blockwise attention、reduction、copy、comm、wait）
• 使用 FlashAttention/Triton 实现高性能 kernel 		GPU 训练迭代中

5. 用户接口

DCP 提供简洁的 API（论文 Listing 2）：

# 1. 替换 attention 实现
core_attn_out = DCPAttn.apply(dcp_executor, q, k, v)

# 2. 定义掩码函数（输入序列信息 → 掩码矩阵）
def mask_fn(seqlens, ...):
    return mask

# 3. 训练脚本
dcp_dataloader = DCPDataloader(dataset, mask_fn)
dcp_executor = DCPExecutor(grouped_ranks)
for local_data, execution_plan in dcp_dataloader:
    loss = model(local_data, dcp_executor)

Planner 可以提前 κ 迭代（如 κ=8）预取输入信息并规划，与 GPU 训练完全重叠，消除规划开销。

技术亮点

1. 负载感知的通信优化

超图分区同时优化计算和通信：

  • 计算块权重精确建模不同掩码下的 FLOPS（causal mask 中上三角被 mask，计算量减半）
  • 层级分区优先最小化跨机器通信（机器间带宽 << 机器内带宽）

2. 零计算浪费

被 mask 的计算块不生成（如注意力掩码 Mij = 0），对应数据块无需传输：

  • Causal mask：上三角计算块全部跳过
  • Shared question mask：不同答案候选之间的交叉注意力跳过
  • Block-wise sparse mask：不相邻的文档块之间跳过

3. 与其他并行正交

并行类型与 DCP 的关系建议等级顺序
Tensor Parallelism (TP) 可在 head 维度联合使用，DCP 的 head 维度块大小应整除 TP degree TP → CP → DP → PP
（Megatron-LM 风格）
Data Parallelism (DP) DCP 占用传统 DP 的设备等级，可在 DP group 间应用不同 CP 配置
Pipeline Parallelism (PP) 不同 stage 可用不同 CP 配置，但需共享执行计划避免高通信成本
Expert Parallelism (EP) 正交，MoE 层不涉及 CP

4. 规划开销消除

Planner 在 CPU 上运行，使用 lookahead 预取机制：

  • 训练迭代 i 时，Planner 预取迭代 i+κ 的输入信息（序列长度、掩码）
  • 规划时间与 GPU 训练完全重叠（异步流水线）
  • 论文实验显示：κ=8 时，规划开销 < 1% 训练时间

适用场景

DCP 最适合的工作负载

长上下文预训练如 Llama 3 的 128K 上下文 tuning 阶段（高成本样本占比小但至关重要）
指令微调数据集包含大量短序列（<4K）+ 少量长序列（>100K），如 LongAlign、LongDataCollection
多任务训练不同任务使用不同注意力模式（RLHF 的 shared question、检索的 block-wise、标准 causal LM）
批处理推理论文聚焦训练，但 DCP 的动态分区思想可扩展到推理（不同请求长度差异大）
