NVIDIA Dynamo 功能实现讲解

数据中心级推理编排层（Rust）。能力标注：✅ 块级KV感知✅ Token负载感知✅ 多实例HA✅ SLA自动扩缩✅ 多后端

块级 KV 感知 —— KV indexer 怎么实现

Dynamo 的 KV indexer（python -m dynamo.indexer）订阅 worker 的 ZMQ PUB 事件流，维护每 (model_name, routing_group) 一棵 radix 树，索引 三层存储：device（GPU）、host-pinned（CPU）、disk。

  • 事件来源：引擎在 KV 块创建/驱逐时原生发 ZMQ 事件（vLLM 和 SGLang 都发，无需 Dynamo wrapper）。
  • 分层语义：/query 返回 gpu ≤ cpu ≤ disk 的累积分层重叠——cpu/disk 是 device 前缀的"延伸"，不是独立命中。这直接支撑了"GPU 全额、offload 打折"的 cache-credit。
  • 容错：P2P 恢复（新副本从 peer 拉 /dump 快照重放）+ gap 检测（ZMQ 有损，靠 seq 号检测丢包，有 replay_endpoint 时回放缺失 batch）。
来源：standalone-indexer 文档（分层语义见 "Per-instance tier breakdown"，容错见 "P2P Recovery"/"Gap Detection and Replay"）

Token 负载感知 —— selection service 的 cache-credit 公式

selection service（python -m dynamo.select_service）把 KV 重叠度折算成加权 prefill 负载：

  • overlap（gpu/cpu/disk 原始重叠）是"观测值"；
  • effective_prefill_tokens 是"权威的加权 prefill 负载"，官方定义它 "computed by the same cache-credit formula used for scheduler booking"——即命中 GPU 块全额抵扣、offload 块打折抵扣后的"还欠多少 prefill"。
  • 再叠加各 worker 的活跃 decode 负载（生命周期记账：prefill_complete / output_block / DELETE），合成 token 负载，选最低者。
  • 打分权重 DYN_ROUTER_* 系列（KV_OVERLAP_SCORE_CREDIT 控制 cache-credit 系数，可归零=纯负载路由）。
来源：standalone-selection 文档（effective_prefill_tokens 定义见 "Selection API"，权重见 "Tune the scoring weights"）

多实例 HA / 状态同步 —— 最终一致的两条通道

  • Replica sync（ZMQ）：selector 副本间共享 admission / prefill-complete / free 事件；output-block 增长故意不同步（高频更新，广播太费带宽，只本地记账）。
  • Indexer recovery（HTTP /dump）：新副本启动时从 peer 拉快照重放 KV 事件。
  • 一致性不变量明确写死：同步是 "bounded and best-effort"——延迟、重排、丢事件、临时分歧都可接受。
来源：standalone-selection 文档（"Peer Planes" / "Consistency Invariants"）

SLA 自动扩缩 —— Planner

Planner 是 SLA 驱动的 autoscaler：对工作负载做 profiling，按延迟 SLO 以最小 TCO 自动调整 prefill/decode 池规模。

来源：Dynamo README（"Planner — SLA-driven autoscaler"）

多后端 —— 引擎无关

Dynamo 是引擎之上的编排层，不替代引擎。通过 backend 接口接 vLLM / SGLang / TensorRT-LLM，三者均支持 disaggregated serving、KV-aware routing、Planner 等能力。

来源：feature-matrix.md（SGLang/vLLM/TRT-LLM 能力矩阵）

小结：为什么块级 + 负载打分是它的核心

Dynamo 把「KV 重叠度」定位为负载估计的输入而非路由目标——KV indexer 负责精确记住"谁缓存了什么块、在哪层"，selection service 用 cache-credit 公式把它折算成"还欠多少 prefill"，再加 decode 负载，选 token 负载最低的副本。这条"块级 KV 事件 → 全局 radix 树 → cache-credit 折算 → token 负载打分"的链路，正是 Anyscale 那篇博客（Ray Serve KVAwareRouter）复用的底层。
