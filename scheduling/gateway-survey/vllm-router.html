vLLM Router 功能实现讲解

vLLM 官方的高性能请求转发系统（Rust）。能力标注：⚠️ 前缀缓存感知✅ 多实例HA✗ 块级KV感知✗ Token负载感知

同源说明：vLLM Router（vllm-project/router）与 SMG / SGLang Model Gateway 同源——负载均衡策略（round_robin / random / consistent_hash / power_of_two / cache_aware）是同一套代码，代码结构（Rust + py_src + py_test）也一致。vLLM Router 是这套框架面向 vLLM 的分发。

前缀缓存感知 —— cache_aware 策略

cache_aware 策略优化前缀缓存命中，带会话亲和（session affinity）：维护前缀匹配，把重复 prompt / few-shot 请求路由到已缓存其前缀的 worker。这是前缀级（非块级 KV 事件）。

来源：vLLM Router README（"Load Balancing Policies" 表，cache_aware 行）

负载均衡策略（5 种）

  • round_robin：顺序轮转（通用、均匀分布）。
  • random：均匀随机。
  • consistent_hash：同 session/user 路由到同 worker（多轮对话、KV 复用），可用 X-Session-ID header。
  • power_of_two：抽两个取较闲的（负载敏感）。
  • cache_aware：前缀缓存命中优化（重复 prompt）。
来源：vLLM Router README（"Load Balancing Policies"）；详见 docs/load_balancing/README.md

PD 分离（prefill/decode disaggregation）

支持 prefill/decode 分离路由，三种 KV connector：

  • NIXL：静态 prefill/decode URL 列表。
  • NCCL：ZMQ discovery（--vllm-discovery-address）。
  • Mooncake：--kv-connector mooncake，启动时查每个 prefill 节点的 Mooncake bootstrap server 拿 engine_id，往请求注入 transfer_id / remote_bootstrap_addr 做 P/D 协调。

还支持数据并行 rank 感知路由（--intra-node-data-parallel-size，把 URL 展开成 url@rank 逻辑节点）。

来源：vLLM Router README（"Prefill-Decode Disaggregation"）

多实例 HA / Service Discovery

K8s 原生：--service-discovery 自动发现 worker（label selector），Semantic Router Operator 用 CRD 管理实例生命周期。另配熔断（Closed/Open/Half-Open 状态机）、指数退避重试 + jitter、Prometheus 指标。

来源：vLLM Router README（"Kubernetes Service Discovery" / "Circuit Breaker"）

小结

vLLM Router 是「vLLM 官方的高性能转发层」：5 种负载均衡策略（cache_aware 做前缀优化）+ PD 分离（NIXL/NCCL/Mooncake 三种 KV 传输）+ K8s 服务发现。但它和 SMG/SGLang Router 一样是前缀级 cache 感知，无块级 KV 事件，无 token 级负载打分。
