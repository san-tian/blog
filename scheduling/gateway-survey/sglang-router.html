SGLang Router（sgl-model-gateway）功能实现讲解

SGLang 的模型路由 Gateway（Rust）。能力标注：✅ 前缀缓存感知✗ 块级KV感知✗ Token负载感知✗ 多实例HA同步

同源说明：SGLang Model Gateway 的代码与 SMG 同源（文档中大量 smg launch、SMG_* 环境变量、smg_* 指标前缀）。SGLang 深度优化它适配 SGLang runtime，同时可路由任意 OpenAI 兼容后端。

前缀缓存感知 —— cache_aware 策略怎么实现

cache_aware 是默认策略，把「缓存局部性」和「负载均衡」组合在一起：维护一棵 radix cache tree，按前缀匹配度 + 负载平衡阈值打分选 worker。

  • --cache-threshold（默认 0.3）：前缀匹配比例低于此值视为未命中。
  • --balance-abs-threshold（64）/ --balance-rel-threshold（1.5）：负载差超过阈值才 rebalance，即"粘缓存直到负载失衡"。
  • --eviction-interval-secs（120）、--max-tree-size（67M 节点）：radix tree 驱逐周期和容量。

官方给出效果：cache_aware 对重复 prompt 约 30% 延迟降低。这是 gateway 层的前缀 tree，不订阅引擎 KV 事件（引擎内的 RadixAttention 是另一回事，属引擎内部复用）。

来源：SGLang Model Gateway 文档（"Load Balancing Policies" / "Cache-Aware Policy Tuning" / "Performance"）

负载均衡策略（5 种）

random（均匀随机）、round_robin（顺序轮转）、power_of_two（抽两个取较闲）、cache_aware（默认，缓存+负载）、bucket（动态负载桶）。

来源：同上文档（"Load Balancing Policies"）

多实例 HA —— 有水平扩展，但 radix tree 不同步

文档明确：支持多副本跑在负载均衡器后，但 worker registry、radix cache tree、熔断状态、限流计数都是各副本独立的——radix tree 不跨副本同步，预期 cache hit 下降 10-20%。官方建议：可接受这个代价换取 HA；若缓存效率关键，用会话亲和（一致性哈希）把同用户固定到同副本。

来源：同上文档（"High Availability" 小节，"Shared Across Replicas: No (independent)"）

多后端 / 协议

控制面统一管理 regular/prefill/decode worker；数据面跨 HTTP、gRPC、PD（prefill/decode 分离）、OpenAI 兼容后端。OpenAI router 模式可把 OpenAI 兼容端点代理到外部供应商（OpenAI、xAI 等），同时把 chat history 留在本地。

来源：同上文档（"Overview" / "OpenAI Backend Proxy"）

小结

SGLang Router 定位是「SGLang runtime 的原生 gateway」：cache_aware 前缀策略 + gRPC 高性能流水线 + PD 分离。但多副本时路由状态（尤其 radix cache tree）不跨副本同步，cache hit 会降 10-20%——这与 SMG（同步了 routing tree）形成鲜明对比，也解释了为什么对比表里它的"多实例 HA 同步"是 ✗。
