DLRouter 功能实现讲解

OpenAI 兼容的多后端推理 gateway（Python，较新）。能力标注：✅ 前缀缓存感知✅ 多后端✗ 块级KV感知✗ Token负载感知

多后端 —— 可插拔 backend adapter

DLRouter 通过可插拔 backend adapter 接口支持 LMDeploy、vLLM、SGLang、DLEngine 四类后端，每个后端有独立的 backend/config/definition 模块。统一 OpenAI 兼容 API（/v1/models、/v1/chat/completions、/v1/completions）。

来源：DLRouter README（"Supported Backends"）；代码结构 dlrouter/backends/{lmdeploy,vllm,sglang,dlengine}/

前缀缓存感知 —— prefix_cache 策略

路由策略之一 prefix_cache：按 KV cache 前缀局部性路由，把请求发给已缓存其前缀的节点以提高命中率。这是前缀级（非块级 KV 事件）。

来源：DLRouter README（"Routing Strategies" 表，prefix_cache 行）；实现见 dlrouter/routing/prefix_cache.py

负载感知路由 —— 延迟估计（非 token 级）

DLRouter 的负载感知是延迟估计而非 token 级负载：

  • min_expected_latency：选 unfinished_requests / speed 最小的节点（在途请求数 ÷ 节点速度）。
  • min_observed_latency：选最近平均延迟最低的节点。

注意：这没有 prefill/decode token 分离，所以不算"Token 负载感知"。

来源：DLRouter README（"Routing Strategies" 表）

完整路由策略清单（6 种）

round_robin（顺序轮转）、random（加权随机，速度高的节点收更多流量）、consistent_hash（同 key 同节点，亲和/缓存局部性）、min_expected_latency、min_observed_latency、prefix_cache。

来源：DLRouter README（"Routing Strategies"）

其他能力：PD 分离 + 动态节点管理

  • DistServe / PD 分离：LMDeploy（RDMA 迁移）、vLLM（two-stage KV transfer + NIXL DP rank 路由 + heartbeat discovery）、SGLang（bootstrap dual dispatch）。
  • 动态节点管理：REST API 注册/移除/检查/终止后端节点；健康检查 + 连续失败自动摘除。
来源：DLRouter README（"Highlights" / "Dynamic node management"）

小结

DLRouter 定位是「多后端 OpenAI 兼容 gateway + PD 分离编排」：可插拔 backend（LMDeploy/vLLM/SGLang/DLEngine）+ 6 种路由策略（含 prefix_cache、延迟估计）。KV 感知是前缀级、负载感知是延迟估计级，没有块级 KV 事件和 token 级打分。项目较新（2026 年初），多实例同步机制未在文档中说明。
