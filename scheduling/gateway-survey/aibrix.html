AIBrix 功能实现讲解

vLLM 生态的云原生 GenAI 推理基础设施（Go，K8s 原生）。能力标注：✅ 前缀缓存感知✅ SLA自动扩缩⚠️ 多实例HA✗ 块级KV感知✗ Token负载感知

前缀缓存感知路由 —— Envoy ext_proc gateway

AIBrix 的 Router 是 Envoy Gateway 的扩展（通过 external processing 钩子），作为 LLM 流量的单一入口，实现 LLM 感知的路由——按前缀缓存匹配把请求路由到已缓存其前缀的 vLLM pod。它通过 vLLM 指标采集感知缓存和负载状态（不是订阅 KV 事件，所以是"前缀级"而非"块级"）。

来源：AIBrix README（"LLM Gateway and Routing"）；Envoy ext_proc 机制见 AIBrix 文档

SLA 自动扩缩 —— LLM App-Tailored Autoscaler

提供 PodAutoscaler CRD：针对 LLM 应用（而非通用 CPU/内存指标）的自动扩缩，基于实时推理需求动态扩缩副本。另配套 RayClusterFleet、ModelAdapter 等 CRD 管理模型与分布式推理。

来源：AIBrix README（"LLM App-Tailored Autoscaler"）；CRD 见仓库 api/autoscaling/v1alpha1/podautoscaler_types.go

多实例 HA（⚠️）

Envoy gateway 作为 K8s Deployment 可多副本部署（网关层 HA）；但 AIBrix 的核心是 K8s operator + CRD 的控制面，路由状态同步机制不如 Dynamo/SMG 那样有显式的跨副本路由状态协议。

来源：AIBrix README（架构）

其他能力：分布式 KV Cache

AIBrix 还提供 Distributed KV Cache（跨引擎 KV 复用）和高密度 LoRA 管理、GPU 硬件故障检测等。注意：分布式 KV Cache 属于"KV 传输/存储"层，与"调度/负载感知"是不同维度。

来源：AIBrix README（"Distributed KV Cache"）

小结

AIBrix 定位是「vLLM 的 K8s 控制面/基础设施」而非独立 router：路由（Envoy ext_proc 前缀缓存感知）+ 扩缩（PodAutoscaler）+ 分布式 KV Cache 组合。它强绑定 K8s + vLLM 生态，是 Lodestar 的底座。
