k-LPM：前缀复用 + 延迟约束下的 LLM 查询调度

NeurIPS 2025 理论 NP-hard 实例内调度

论文：Dexter et al., "LLM Query Scheduling with Prefix Reuse and Latency Constraints"。arXiv:2502.04677。这是目前少有的从理论上研究「前缀复用 + 排队调度」的工作——它证明了这个调度问题是 NP-Hard，并给出一个用单参数 k 在「复用」和「公平」之间插值的算法。

背景：RadixAttention 下，调度顺序决定性能

RadixAttention（SGLang 的前缀复用机制）用 radix tree 存 KV cache，自动复用新请求与已缓存请求的共享前缀，LRU 淘汰。它「开箱即用」地省 prefill 计算，但性能高度依赖 query 的处理顺序（schedule）。

两种主流调度策略，各有致命缺陷：

策略默认于做法缺陷
FCFSvLLM v0.6.6按到达顺序处理完全忽略前缀复用，高负载（burst）下 TTFT 尖峰
LPMSGLang v0.4.1每步贪心选「和当前缓存前缀重叠最大」的 query离线（所有 query 已知）时最优（Zheng et al. 2024 Thm 3.1）；但在线 + TTFT 约束下会饿死前缀重叠不够高的 query——它们永远排不上
核心张力：LPM 偏向「复用」（省计算但饿死不匹配的请求），FCFS 偏向「公平」（无人饿死但放弃复用）。这正是「复用 vs 公平」在单实例队列排序这一层的体现。

形式化模型：让理论分析成为可能

论文先建立两个定义，把 RadixAttention 调度问题形式化：

Definition 1：query stream

Q = { (x_i, t_i) }  i=1..n
  x_i = prompt（token 串），t_i = 到达时间

Definition 2：LLM 实例计算模型

单实例、连续 batching，按顺序 x_j1..x_jn 处理。第 j_k 个 query 的处理成本：

R(j_k) = max{R(j_{k-1}), t_{jk}} + (1 + c_attn·|x_jk|)·(|x_jk| − Overlap(x_jk, x_jk−1))
  • 处理成本 ∝ prompt 长度 − 与上一个 query 的前缀重叠（复用省掉的量）。
  • 注意力项（二次）由 c_attn 捕获；MLP 项线性。
  • 简化假设：只缓存「上一个」query（而非固定内存池），避免引入额外超参。
  • 模型聚焦 prefill-dominant（长 prompt 短输出）场景——正是 RadixAttention 收益最大的场景。

核心贡献 1：问题 NP-Hard

把「判断是否存在满足 TTFT 约束 T 的调度」归约到 3-PARTITION，证明（Theorem 1）：

在 RadixAttention（前缀复用）下，判断一个 query stream 能否满足 TTFT 约束是 NP-Hard。

证明直觉：前缀复用 + 非均匀到达时间，可以构造「必须在特定时刻处理」的 query 对（x 在 t 到达、y 在 t+T 到达且 x、y 同 prompt——要复用就必须 x 恰好在 t+T 处理完、y 立刻接上），从而把「m 个时间窗口各填满长度 H」的约束强加给调度，而这正是 3-PARTITION。

难在「三者叠加」：无前缀复用时 FCFS 平凡最优；均匀到达（离线）时 LPM 最优。只有「前缀复用 + 在线到达 + TTFT 约束」三者同时出现，问题才变难——而这正是真实在线 serving 的场景。

核心贡献 2：k-LPM 算法（复用 ↔ 公平的插值）

每处理 k 个请求，其中：
  1 个：处理「等待最久」的 query          （FCFS 的兜底，防饿死）
  k−1 个：贪心选「前缀命中率最大」的 query  （LPM 的复用）

k = 1  → 退化为 FCFS（纯公平）
k = ∞  → 退化为 LPM（纯复用）

直觉：每 k 步强制处理一次最老的 query，给「前缀不匹配」的请求兜底，堵住 LPM 的饿死漏洞；其余 k−1 步仍贪心复用，保留 LPM 省计算的优势。k 就是「复用 vs 公平」的旋钮。

注意：论文正文的直觉描述（"先 k 步 LPM 再处理最老"）与伪代码（先最老再 k−1 步 LPM）顺序略有差异，但净效果一致——每 k 个请求里 1 个兜底、k−1 个复用。

核心贡献 3：理论保证（Theorem 2）

在「Regular Arrival Shuffled Queue」数据生成模型下证明最优性：

  • 树形 prompt：每个 query = (user)(doc)，user 子串（长度 u）被恰好 k 个 query 共享，doc（长度 d）每 query 唯一。
  • 到达：均匀随机排列，到达间隔 s。
  • 这是「捕获真实流量关键性质的最简模型」——树形前缀 + 随机到达。
算法最大 TTFT 界性质
LPM≥ T + (1−ε)·n·(u/k + d)下界（高概率）
FCFS≥ T + (1−ε)·n·(u + d − s)下界（高概率）
k-LPM≤ T + n·(u/k + d − s/k)上界（确定性）
Corollary 3：当 0 < s < u 且 k > 1（中间负载）时，k-LPM 的上界严格低于 FCFS 和 LPM 的下界——即 k-LPM 同时优于两者。
直觉：低负载（s 大）FCFS 好（复用不重要）；高负载（s 小）LPM 好（复用省计算）；中间负载 k-LPM 最优——它随负载自动处于正确的位置。

此外还有近似算法（Theorem 4）：对 (1−p) 分位 TTFT ≤ T 的调度，要么证明无解、要么返回可行调度，时间 O(n·exp(1/p · log 1/p))。

实验：k=2 就够

  • Llama-3.1-8B-Instruct + 8×A100（TP）+ SGLang v0.4.1，360Brew 的 8k-context prompt（Instruction / Member Profile / Past Interactions 为共享前缀，仅 Question 变化），2000 prompts。
  • k=2 就足够：在广泛 request rate 下 P99 TTFT 最低；大 k（如 1000）退化为 LPM。
  • FCFS 低负载好、LPM 高负载好、k-LPM 全负载稳健——与理论预测一致。
  • 即使真实 prompt 只是"近似树形"、k 与真实副本数不符（真实 4 副本、k=2/3），k-LPM 仍显著改善 P99 TTFT。

和你的研究的关系

三个直接相关的点：
  • 「复用 vs 公平」的张力在实例间路由同样成立：把请求全路由到「KV 命中最多的实例」就是实例间版的 LPM，会饿死前缀不匹配的实例（负载不均）。你的细粒度路由要解决的正是这个。
  • k-LPM 的「k 步贪心 + 1 步兜底」是一种「阈值过滤 + 择优」——和 llm-d 的 sticky-until-saturated（粘性复用 + 饱和释放）是同一思想的两个层次：llm-d 在实例间做，k-LPM 在实例内做。
  • 它给了「复用 vs 公平」一个理论底座：NP-Hard 证明说明这不是工程技巧，而是本质困难——这为你的「细粒度负载路由」提供了 motivation 的权威背书（问题足够难，值得做）。
