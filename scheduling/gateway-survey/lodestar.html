Lodestar 功能实现讲解

在线学习路由（Go gateway + Python 训练服务，构建在 AIBrix 上）。能力标注：✅ 前缀缓存感知✅ Token负载感知✅ 在线学习路由✗ 块级KV感知✗ 多实例HA

在线学习路由 + Token 负载感知 —— MLP 预测 −TTFT

核心是一个小 MLP（3 隐藏层 × 128 单元，ReLU，dropout 0.1，标量输出），对每个候选实例预测 reward = −TTFT，选 argmax（即预测 TTFT 最小）。

  • 请求特征：input token length、期望 KV cache 命中率。
  • 实例状态（token 级负载，关键设计）：inflight prefill tokens 和 inflight decode tokens 分开保留——因为 prefill 是计算密集、decode 是内存带宽密集，合并会掩盖实例正逼近哪个瓶颈；再加 running/queued requests、GPU 型号、GPU 内存利用率。
  • 参数跨实例共享，instance ID 从不作为输入：实例数无关（弹性扩缩无需重训）+ 实例索引无关（避免"羊群效应"）。
  • 故意排除 GPU utilization / SM activity（GPU utilization 只要任一 kernel 在任一 SM 上跑就报 100%，误导大；细粒度 profiler 开销与在线路由不兼容）。
来源：Lodestar 论文（arXiv 2606.00946）（§The reward predictor；特征选择）

前缀缓存感知 —— KV cache tracker

Stateful Gateway 的 KV cache tracker 把 prompt tokenize 后插入 radix tree 前缀索引，算"路由到该实例能命中多少已缓存前缀"——这是前缀命中率（非块级 KV 事件），作为 MLP 的输入特征之一。

来源：Lodestar README（"expected KV cache hit ratio"）

在线训练 —— 解决"循环依赖"

Lodestar 的核心设计选择是在线学习：离线训练的预测器不泛化，因为路由策略本身会重塑它要预测的负载分布（论文 §3.3 的"circular dependency"）。实现：

  • 触发：每新增 θ=1000 个样本重训一次。
  • two-pool buffer：FIFO（5000 最近样本，recency）+ replay（5000 样本，经 gradient-coreset 准则按激活/残差选最多样的，diversity）。
  • 回退：冷启动无模型、特征越界（OOD）、RPC 超时三种情况回退到启发式（pre-computed 选择，不增延迟）。
来源：Lodestar 论文（§Online learning loop）

架构与部署

  • Stateful Gateway（Go，~8K 行）：Envoy data plane 的 ext_proc 插件，拦截每个请求 → 采集群快照 → 问 Routing Service → 转发 → 记 TTFT/TPOT。
  • Routing Service（Python，~4K 行）：持有 MLP + 训练循环，暴露 /infer（打分）和 /flush（批量日志 → 训练）。
  • 构建在 AIBrix 上，复用其 Envoy ext_proc gateway、pod registry、vLLM 指标采集；跑在 K8s。
来源：Lodestar README（"Architecture"）

小结

Lodestar 是「学习式路由」的代表：用 MLP 把 KV 命中率 + token 级负载（inflight prefill/decode 分开）+ 硬件状态一起学成 −TTFT 预测，在线训练应对分布漂移。它是单实例 gateway（无跨副本路由状态同步），这是相对 SMG/Dynamo 的短板；但"把 prefill/decode token 分开当特征"这个设计，正是"负载感知"的关键细节。
