① 多实例 HA / 状态同步 —— 谁真正解决了「路由状态跨实例一致」

核心矛盾：KV cache 状态是路由决策的输入，但多实例路由时每个实例看到的状态必须一致，否则会做出冲突决策。各家分三档：

  • 最强（SMG）：SWIM gossip + CRDT 同步了包括 cache-aware routing tree 在内的全量路由状态——唯一把「KV 路由树」纳入跨实例同步的方案，3/5 节点容忍 1/2 节点故障。
  • 事件驱动收敛（Dynamo / llm-d / Ray Serve）：Dynamo 的 selection service 用 ZMQ 同步 admission/prefill-complete（output-block 故意不同步）；llm-d 的 KV indexer pod-discovery 模式每副本独立订阅全量 KV 事件各自收敛；Ray Serve ingress 异步同步 token 负载。三者都是「最终一致」。
  • 有限（SGLang Router / Lodestar）：引擎内嵌或单实例 gateway，无跨实例路由状态同步——多实例时 cache 命中退化。

② SGLang KV event 感知 —— 谁在做「块级精确」而非「前缀近似」

  • 块级精确（Dynamo / llm-d）：都订阅 vLLM 和 SGLang 的 ZMQ KV 事件（BlockStored/BlockRemoved/AllBlocksCleared），维护块级索引。llm-d 还支持 multimodal hash、LoRA、分层权重、speculative indexing。
  • 前缀近似（SMG / AIBrix / Lodestar）：维护 radix 树/前缀索引，匹配文本前缀，不感知引擎真实缓存和驱逐。
  • 引擎原生（SGLang Router）：SGLang 的 RadixAttention，引擎内前缀复用（非跨实例 KV event）。
  • 受限（Ray Serve LLM）：KVAwareRouter 的 KV 事件是 vLLM-native；SGLang 能跑但社区支持早期。

③ K8s / Ray 依赖 —— 能否脱离编排框架独立跑

  • 零依赖（Dynamo / SMG / SGLang Router / DLRouter）：引擎无关、纯进程内或独立二进制，K8s 只是可选。
  • K8s 可选（llm-d）：新增 EndpointDiscovery + file-discovery，可无 K8s 运行（Slurm / Ray / 裸机），路由逻辑不变。
  • 强绑定 K8s（AIBrix / Lodestar）：依赖 K8s pod 模型，下游推理服务必须跑在 K8s pod。
  • 强绑定 Ray（Ray Serve LLM）：路由和下游引擎都在 Ray Serve 部署模型内。

④ 调度方式 —— 谁在「cache hit + 负载」双目标上做得最干净

结论与建议

  • 工业侧主流（调度/负载感知）：Dynamo、llm-d、SMG、SGLang Router、AIBrix / vLLM Router、Ray Serve LLM。
  • 学术侧核心会议：OSDI / NSDI / SOSP（系统方向）+ ICML（ML 系统方向）。
  • 最该精读的三篇：Llumnix（OSDI 24，动态重调度）、LMetric（OSDI 26，乘法路由）、AlpaServe（OSDI 23，统计复用）。
  • 你目录里已有的：Lodestar、LMetric、QUARTZ、llm-d、Ray Serve 博客——已覆盖「学习式」和「启发式」两条主线，与本次调研的 A 类高度重合，形成闭环。
贯穿性共识：Dynamo、llm-d、Ray Serve、SGLang Router 四个独立工业实现，加上 LMetric（OSDI 26）、Llumnix（OSDI 24）两篇顶会论文， 在「负载感知路由」上殊途同归——KV 重叠度只是负载估计的输入，真正的路由目标是让 token 负载均衡。
按四个关注点选型：
  • 要「多实例 + 状态同步」最强 → SMG（SWIM+CRDT 同步了 cache-aware 路由树）；次选 Dynamo / llm-d（事件驱动最终一致）。
  • 要「SGLang KV event 块级感知」→ Dynamo 或 llm-d（都订阅 SGLang 的 ZMQ KV 事件）。
  • 要「脱离 K8s/Ray 独立跑」→ Dynamo / SMG / SGLang Router（引擎无关、零编排依赖）。
  • 要「cache hit + 负载均衡」最干净 → 学术是 LMetric 乘法路由（零调参）；工业落地是 llm-d sticky-until-saturated（阈值可推导） 或 Dynamo（cache-credit 打分）。

核实说明：Llumnix=OSDI 2024、LMetric=OSDI 2026、Libra=NSDI 2026、AlpaServe=OSDI 2023、Shepherd=NSDI 2023、 Orca=OSDI 2022、Sarathi-Serve=OSDI 2024、FastServe=NSDI 2026、Sia=SOSP 2023、MuxServe=ICML 2024、Preble=NSDI 2024 均已核实； Intelligent Router、Lodestar、Slice-Level Scheduling 为 arXiv。
