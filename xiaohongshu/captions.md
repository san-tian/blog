## 01 - MTP 为什么会让上下文减小

🔥 开了 MTP 后上下文变短？真相原来是这样！

很多人以为是"模型参数变大了"，其实不是！

真正原因：
✅ MTP 权重只多 1%
❌ 但 KV cache 草稿槽位吃掉 16-28% 显存！

📊 显存分配对比：
• Base 模型：100% 给主干 KV
• GLM-5.2 (7步MTP)：84% 主干 + 6% MTP + 10% 草稿峰值
• EAGLE-3 (树形)：72% 主干 + 6% Draft + 22% 草稿树

💡 核心：
投机解码要为草稿 token 预留 KV 槽位
→ 留给主干的显存变少
→ 可用上下文自然变短

这是用显存换加速的必然代价 ⚡️

## 02 - PD 分离中 decode 不需要 L2 缓存

🤯 一个反直觉的发现：decode 不需要本地 L2 缓存！

SGLang 源码复盘，被硬件事实纠正的技术决策 👇

两条路径对比：
📍 路径 A：prefill GPU 跨机重传 KV
→ 8×IB 聚合带宽 = 1600 Gbps
→ ✅ 实测更快

📍 路径 B：decode 从本地 host DRAM 加载
→ PCIe 5.0 带宽 ≈ 1024 Gbps
→ ❌ 单链路不如路径 A

💡 关键洞察：
多卡 IB 聚合带宽 > 单卡 PCIe 带宽
→ decode 直接从 prefill 拉 KV 更划算
→ 不需要额外的 L2 缓存层！

硬件配置决定架构选择 🎯

原以为"本地一定快"，结果是"聚合带宽说了算"

## 04 - DCP 动态上下文并行

🎯 SOSP'25：破解长上下文训练的输入动态性难题！

传统方案困境：
❌ 静态并行配置 → 序列长度变化时通信低效
❌ 稀疏 attention mask → 负载严重不均衡

DCP 动态解决方案：
✅ 细粒度块级分区
✅ 超图分区优化
✅ 为每个 batch 动态生成最优并行配置

🚀 加速效果惊人：
• Causal mask：1.19×–2.45× 加速
• Sparse mask：2.15×–3.77× 加速

💡 适用场景：
长上下文预训练、指令微调、变长序列等
序列长度和注意力模式变化大的场景

不再需要为最坏情况预留资源
每个 batch 都用最优配置训练 ⚡️
